# Contributing

## Principles

- **Design patterns.** Reach for the catalog at [refactoring.guru](https://refactoring.guru/design-patterns)
  when a design problem has a known name. Use a pattern to solve a problem you have, not to decorate code.
- **SOLID.** One reason to change per class, extension without modification, substitutable subtypes,
  small interfaces, and dependencies on abstractions that are passed in.
- **OOP.** Behavior lives in classes with a clear responsibility. Dependencies come through the
  constructor so every class can be tested with fakes.
- **DRY.** One place for each piece of knowledge.
- **KISS.** Prefer the simplest design that works.
- **Clean Code** by Robert C. Martin. Small functions that do one thing, intention-revealing names,
  no surprises.

## Style

- English everywhere: code, documentation, commit messages, issues and pull requests.
- Readability for humans first. If code needs explaining, rename or extract it.
- **No `//` comments, anywhere.** The `local/no-line-comments` ESLint rule fails the build on them.
  Do not add `#` comments to Python either.
- JSDoc (`/** */`) only on exposed APIs, stating the purpose, the inputs and the outputs. Private
  members get none. Python uses docstrings the same way.

## Tooling

The payload in `src/` is TypeScript and SCSS. `npm run build` compiles it to `dist/`, which is what
the installer deploys. Users never need Node.

| Command | Purpose |
|---|---|
| `npm ci` | Install the pinned dev dependencies |
| `npm run lint` | ESLint (typescript-eslint) and Stylelint |
| `npm run typecheck` | `tsc --noEmit` with `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` |
| `npm test` | Node's test runner through `tsx` |
| `npm run build` | Build `dist/` |
| `make test-py` | Installer tests (Python 3.9+, standard library only) |
| `make check` | Lint, typecheck, all tests and build in one go |

`any` is not allowed. Add tests with every behavior change.

## Commits and pull requests

- A commit message is a **subject line only**, 50 to 80 characters. No body, no trailers, no
  `Co-Authored-By`.
- Keep commits small and logical.
- A pull request description does not contain a "Generated by Claude Code" line or any other
  generation notice.
